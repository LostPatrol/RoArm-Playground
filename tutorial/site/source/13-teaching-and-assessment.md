# 第 13 章 教学安排与考核

> 本章目标：给教师一份可直接执行的四周课表与评分表；给学生一份明确的项目清单、验收条件与交付规范。学完这一章，双方对"做到什么算完成"不应再有分歧。

## 13.1 课时分配

课程默认 12 学时、四周完成，另配课后时间做项目。若只有 8 学时，按"★核心"删减：保留第 1、4、7、8、9、11 章，压缩第 5、12 章为演示。

| 周次 | 主题 | 学时 | 主要章节 | 课堂形式 |
|---|---|---|---|---|
| 第 1 周 | 认识自己的工具链 | 3 | 0、1、4、6 | 讲授 + 两次现场调用演示 |
| 第 2 周 | 让 Agent 按规格开发 | 3 | 5、7、8 | 讲授 + 结对改写需求 |
| 第 3 周 | 调试、上下文与分工 | 3 | 9、10（选）、12 | 讲授 + 故障复盘 |
| 第 4 周 | 交付与现场验收 | 3 | 11、13 | 演示 + 现场变化任务 |

每周 3 学时的建议切分：讲授 70 分钟、动手 50 分钟、复盘 60 分钟。动手环节不能省——这门课的多数结论只有自己踩过一次才信。

## 13.2 四周课表（细目）

| 周次 | 核心内容 | 项目进度 | 课后任务 |
|---|---|---|---|
| **第 1 周：认识自己的工具链** | 模型与 Agent 的区别；基本原理；一次 API 调用；小型模型对比 | 跑通教师提供的项目底座，修改一个看得见的功能 | 确定自己的目标用户，写出三个核心功能与验收条件 |
| **第 2 周：让 Agent 按规格开发** | 文件与终端基础；任务拆解；项目指令；Git、diff、测试 | 完成一个从输入到结果的完整功能，而不是只有界面 | 找一位试用者，记录实际问题，不急着加新功能 |
| **第 3 周：调试、上下文与分工** | 故障定位；状态交接；上下文整理；一个 subagent；权限边界 | 修复真实问题，补充边界测试，完成主要功能 | 整理一次"失败—定位—修复"记录 |
| **第 4 周：交付与现场验收** | 部署或安装；成本与数据检查；恢复与回滚 | 完成最终版，接受教师现场变化任务 | 交付源码、说明、测试证据与已知问题 |

课表的节奏是有意的：第 1 周先让项目跑起来（哪怕很丑），第 2 周把一条链路打通，第 3 周只修不扩，第 4 周交付。**最常见的失败是第一周就在设计架构、第四周还没有一条能跑的链路。**

教师的三个提醒：

1. **第 1 周的"项目底座"必须提前准备好**，学生不能把课时花在装环境上。网络、账号、模型访问由教师课前处理。
2. **第 2 周的"一个完整功能"要当硬指标**。只有界面的项目在第 2 周末就应被指出，而不是等到第 4 周。
3. **第 4 周的现场变化任务要提前设计**，必须单点、可撤回、效果可见、有对应测试（参见 12.7 节的三样证据）。

## 13.3 六个项目方向

学生从下列方向中选一个。每个方向都给出"首月交付"的底线、"后续扩展"的空间和"必须验收"的具体条件。**验收条件是可以当场演示的，不是形容词。**

| 项目 | 首月交付 | 后续扩展 | 必须验收的内容 |
|---|---|---|---|
| **家庭通讯软件** | 手机和电脑浏览器可访问的私人聊天空间；先做文字与图片 | 视频通话、推送、原生客户端、多设备同步 | 两个真实设备互发；刷新后记录符合设计；未授权用户不能读消息 |
| **沙盒 / FPS 游戏 Demo** | 单机、小地图、一个主要玩法。沙盒做放置/破坏与存档；FPS 做移动、靶场计分与重开 | 多人、地图编辑器、复杂物理与更多玩法 | 输入与碰撞正常；胜负或计分规则有效；能恢复或重新开始 |
| **机械臂控制程序** | 在官方控制接口上增加自己的界面或动作序列 | 示教、视觉定位、高层自然语言任务 | 限位、限速、停止与断联处理；重复运行符合预期 |
| **知识库 / 笔记软件** | 笔记管理、搜索、持久化；进阶加入基于指定笔记的引用式问答 | 混合检索、复习计划、多设备同步 | 已知问题答对；引用确实支持结论；资料不足时不编答案 |
| **随动视觉系统** | 先完成姿态读取、角度映射、云台随动与桌面视频显示 | 头戴显示、延迟优化、更完整的交互 | 回中、角度边界、断联停止；记录端到端表现 |
| **个人博客** | 内容管理、响应式页面、发布与更新流程 | 搜索、自动化部署、作品集、更多交互 | 换设备能用；修改能发布；失败能回滚；不泄露个人信息 |

选方向的建议：**选你能找到真人试用的那个。** 家庭通讯软件可以给家人装，博客可以给同学看；没有人试用的项目，最后只能自己验收，而自己验收的标准通常会一路降低。

## 13.4 可选的非 LLM 模型作业

以下任务任选其一或两项，目的是让你亲手体会"模型不只有聊天"：

| 任务 | 你要做的 | 验收 |
|---|---|---|
| 语音识别 | 用现成模型把一段中文录音转成文字 | 给出原文与识别结果的对比，指出错在哪里 |
| 语音合成 | 把一段文字合成为音频并播放 | 能听清，语速可调；说明用了本地还是云端 |
| 图像分类 | 用现成模型给 10 张图分类 | 列出正确率与错例，分析错因 |
| 目标检测 | 用现成模型在一段视频上画框 | 框的位置大致正确；说明漏检情况 |
| 图像生成 | 用同一提示词生成 4 张图，改变一个参数再生成 4 张 | 说清参数改变了什么 |
| 图像抠图 / 分割 | 把一张照片的前景抠出来 | 边缘质量可接受；说明失败场景 |
| 人声与伴奏分离 | 分离一首歌 | 两条音轨都能听；说明串音 |
| 音频降噪 | 处理一段有噪声的录音 | 对比处理前后；说明是否损伤人声 |
| 本地小模型 | 在自己电脑上跑一个 1–7B 的对话模型 | 能连续对话；报告显存/内存占用与速度 |
| Embedding 检索 | 用向量检索在一批文档里找答案 | 三个查询的命中结果与理由 |

非 LLM 作业的报告只需三段：**输入是什么、输出是什么、哪里失败了。** 不需要训练，不需要调参，重点是"见过并说清楚"。

## 13.5 评分标准

总分 100，四项加权。教师可根据课时调整权重，但**"能演示"这一项的权重不应低于 40%**。

| 维度 | 权重 | 评分要点 | 低分特征 |
|---|---|---|---|
| 功能完成度 | 35 | 首月交付清单中的功能是否真实可用 | 只有界面；数据不持久；刷新丢失 |
| 现场验收 | 40 | 当场完成教师给的临时变化任务；边界行为正确 | 改动后原功能坏了；断网/越权无处理 |
| 证据与记录 | 15 | 测试输出、失败复盘、已知问题清单 | 只说"已完成"；无失败记录；报告美化 |
| 表达与协作 | 10 | 能讲清人做了什么、AI 做了什么、还差什么 | 把 Agent 的产出说成自己的；说不清限制 |

现场验收的题型示例（教师按项目方向替换具体对象）：

- 把主色从 A 改成 B，并在两台设备上确认生效；
- 让程序在输入为空时给出提示而不是崩溃；
- 断开网络 10 秒，观察系统反应并解释；
- 用一个未授权的账号尝试读取别人的数据；
- 回滚到上一个版本，并说明回滚后哪些数据受影响。

> 要点：评分的核心不是"做得多大"，而是"改得动、说得清、坏得体面"。

## 13.6 交付物清单

结课时提交一个压缩包或一个仓库链接，包含：

1. **源码**，能按说明在干净环境跑起来；
2. **运行说明**，三步以内能启动；依赖版本写清楚；
3. **测试证据**，自动化测试输出或手动验收记录（截图/日志）；
4. **已知问题清单**，按严重程度排序，写清"没做"和"做了但不稳"的区别；
5. **一次失败记录**，现象、定位过程、修法或决定不修的理由；
6. **成本说明**（如使用了 API），估算方法与大致用量，不写具体单价。

缺第 4、5 项的材料按"证据不足"扣分。这不是苛刻：一个说自己"全部完成"却列不出已知问题的项目，通常意味着**没有认真测过**。

## 13.7 结课能力表

下表是课程希望达到的终点。教师可用它做最终面谈，学生可用它自查。

| 能力 | 可观察的结课表现 |
|---|---|
| 模型理解 | 能区分模型、聊天产品、API、Agent、普通程序，说明哪些模块在本地、哪些在云端 |
| 模型使用 | 能调用至少两种模型服务进行比较，并完成一次本地模型推理 |
| 工程协作 | 能向 Agent 提交明确任务，查看修改、运行测试、保留版本并恢复 |
| 多模态认识 | 亲手运行至少一种非 LLM 模型，说明输入、输出、适用范围与失败情况 |
| 独立判断 | 能发现一项不可靠输出，并用资料或实际测试核验 |
| 产品交付 | 能运行自己的项目，完成一个临时变化任务，说明已知限制 |

更细的行为版本：

| 能力 | 学生应能表现出来的行为 |
|---|---|
| 基本认识 | 能用自己的话区分模型、使用模型的软件、普通程序与 Agent |
| 电脑操作 | 能找到项目文件，打开、修改、保存、运行，并保留可恢复的版本 |
| AI 协作 | 能说明目标、现状、限制和验收要求，而不是只说"帮我做好" |
| 输出判断 | 能指出一项不可靠结果，并通过资料、规则或实际运行检查 |
| 作品修改 | 能在现成项目上修改一条规则、增加一个小功能，并验证结果 |
| 模型实验 | 能在已准备好的环境中重新运行本地模型，完成一次非 LLM 实验 |
| 结果说明 | 能讲清自己做了什么、AI 做了什么、哪些问题尚未解决 |

## 13.8 教师备忘

- **课前**：准备项目底座、预装环境、可用的模型访问渠道、打印好的验收单。学生不该在第一节课装环境。
- **课中**：每个结论配一次现场演示。AI 的可靠性问题是抽象的，但"它在空墙上认出一张脸"是具体的。
- **课后**：对学生的交付只问三个问题——能演示吗？改得动吗？坏的时候会怎样？
- **红线**：不鼓励绕过地区限制、不鼓励把他人数据上传到不可信服务、不鼓励在无授权设备上做实验。这些不是课程内容，是底线。

## 课后题

（本章为教学安排章，课后题为教师自省与设计练习。）

1. 把 13.2 的课表改成你实际可用的周数（例如 8 周、每周 2 学时），说明你删了什么、为什么能删。
2. 为你的课堂设计一个"现场变化任务"，写清：改什么、怎样算成功、失败时怎么回滚。
3. 对照 13.6，检查你自己最近交付的一个项目缺了哪几项。
4. 思考题：如果学生用 Agent 完成了 90% 的代码，这个项目还算他的作品吗？你的评分标准如何体现这一点？
