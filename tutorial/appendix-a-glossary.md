# 附录 A 术语表

> 用法：遇到不熟的词先在这里查一句话解释，再回对应章节看上下文。这里的定义刻意简略，不追求学术严格性。

## A.1 模型与任务

| 术语 | 一句话解释 | 章节 |
|---|---|---|
| 模型（Model） | 一组从数据里学出来的参数，给定输入产生输出 | 1 |
| 参数 / 权重 | 模型内部可调的数字，训练就是调它们 | 2、3 |
| 推理（Inference） | 用训练好的模型算一次结果，不改参数 | 3、4 |
| 训练（Training） | 用数据反复调整参数，让输出更接近期望 | 3 |
| LLM（大语言模型） | 以文本为输入输出、参数量很大的模型 | 1、4 |
| 多模态（Multimodal） | 能处理两种以上输入或输出形式（如文字+图片） | 10 |
| ASR（语音识别） | 音频 → 文本 | 10 |
| TTS（语音合成） | 文本 → 音频 | 10 |
| 目标检测（Object Detection） | 图片 → 框 + 类别 | 10 |
| 分割（Segmentation） | 图片 → 每个像素属于什么 | 10 |
| Embedding（嵌入） | 把文字/图片变成一串数字向量，便于比较相似度 | 2、10 |
| 分类 / 回归 | 输出离散类别 / 输出连续数值 | 3 |
| 聚类 | 没有标签，把相似的数据分到一起 | 3 |

## A.2 数学与训练

| 术语 | 一句话解释 | 章节 |
|---|---|---|
| 向量 / Tensor | 一串数 / 多维数组，是模型运算的基本单位 | 2 |
| 梯度下降 | 沿着"让误差变小"的方向一小步一小步调整参数 | 2 |
| 学习率 | 每步走多大；太大越过最优，太小走不动 | 2 |
| 损失（Loss） | 衡量输出与期望差多少的数字 | 2 |
| 反向传播（BP） | 从误差倒着算出每个参数该往哪调 | 2、3 |
| 激活函数 | 给网络加入非线性，否则多层等于一层 | 3 |
| 卷积（Convolution） | 用小窗口在图上滑动提取局部特征 | 3 |
| 过拟合 / 欠拟合 | 训练集太好、新数据很差 / 两边都差 | 2、3 |
| 超参数 | 训练前人为设定的值（学习率、层数等） | 2 |
| 迭代 / Epoch | 更新一次参数 / 把训练集完整过一遍 | 2、3 |
| 有监督 / 无监督 / 半监督 | 有标签 / 无标签 / 少量标签 | 3 |
| 强化学习（RL） | 通过奖励与试错学习策略 | 3 |
| CNN / RNN / LSTM | 卷积网络 / 循环网络 / 带门控的循环网络 | 3 |
| Transformer | 以注意力为核心的网络结构，现代 LLM 的基础 | 4 |
| 注意力（Attention） | 计算每个词该"看"其他哪些词、看多重 | 4 |
| 位置编码 | 告诉模型词的先后顺序 | 4 |
| 预训练 / SFT / RLHF | 大规模学语言 / 学按指令回答 / 按人类偏好调整 | 4 |
| LoRA | 只训练一小部分附加参数的低成本微调方法 | 10 |
| 量化（Quantization） | 用更少的位数存参数，换更小的体积和更快的速度 | 10 |
| 蒸馏（Distillation） | 用大模型的输出教小模型 | 10 |

## A.3 使用与产品

| 术语 | 一句话解释 | 章节 |
|---|---|---|
| Token | 模型处理文本的最小单位，约等于一个词或半个词 | 4 |
| 上下文窗口 | 模型一次能"看到"的 token 总量上限 | 4、9 |
| Temperature | 控制输出随机性；低更稳，高更多样也更易跑偏 | 4 |
| Top-p | 只在概率最高的一部分候选里采样 | 4 |
| 系统提示 / System Prompt | 在对话最前面设定角色与规则的文字 | 5、7 |
| API | 程序调用服务的接口，按用量计费 | 6 |
| API Key | 调用凭证，等同密码，泄露即被盗用 | 6 |
| 订阅 | 按月付费使用聊天产品，通常不含 API 额度 | 6 |
| 中转站 | 第三方转售 API 的服务，便宜但存在隐私与稳定性风险 | 6 |
| 本地部署 | 把模型跑在自己的机器上，数据不出本地 | 6、10 |
| GGUF | 一种常见的本地模型文件格式 | 10 |
| 显存（VRAM） | 显卡上的内存，决定能跑多大的模型 | 10 |
| Benchmark | 标准测试集上的分数，只说明部分能力 | 10 |
| Hugging Face | 模型与数据集的公共托管平台 | 6、10 |

## A.4 Agent 与工程

| 术语 | 一句话解释 | 章节 |
|---|---|---|
| Agent（智能体） | 能调用工具、多轮执行直到完成目标的模型程序 | 5 |
| 工具调用（Tool / Function Calling） | 模型输出结构化请求，由程序真正执行 | 5 |
| 循环（Loop） | 观察 → 决策 → 行动 → 再观察，Agent 的基本形态 | 5 |
| MCP | 让 Agent 以统一方式接入外部工具与数据的协议 | 5 |
| SKILL | 打包好的可复用操作说明与脚本，按需加载 | 5 |
| Harness（脚手架） | 围绕模型的一整套工程约束：指令、权限、测试、日志 | 5 |
| 上下文污染 | 无关或错误的信息进入上下文，带偏后续输出 | 9 |
| 交接摘要 | 换新会话时给下一轮的状态说明 | 9 |
| RAG（检索增强生成） | 先检索资料，再让模型基于资料回答 | 9 |
| 子代理（Subagent） | 由主 Agent 派出的独立执行单元，有独立上下文 | 9 |
| 幻觉（Hallucination） | 输出流畅但与事实不符 | 4、8 |
| 知识过时 | 模型训练数据早于当前事实 | 8 |
| 不遵守（Instruction Following 失败） | 明知要求却没照做 | 8 |
| Eval（评测） | 用固定题目与标准衡量输出质量 | 8 |
| VibeCoding | 以自然语言驱动 Agent 完成开发的实践方式 | 11 |
| 回滚（Rollback） | 把代码或数据恢复到之前的版本 | 9、13 |
| 限位 / 急停 | 硬件运动范围的硬性约束与立即停止手段 | 12 |

## A.5 硬件与部署

| 术语 | 一句话解释 | 章节 |
|---|---|---|
| GPU | 图形处理器，因并行能力强而成为训练主力 | 3 |
| CUDA | 英伟达的 GPU 计算平台，很多框架默认依赖它 | 3 |
| NPU | 神经网络加速单元，常见于手机与单板机 | 3 |
| 边缘计算 | 在设备本地算，不把数据传回云端 | 3、12 |
| 集群 / NVLink | 多卡多机协同训练 / 卡间高速互联 | 3 |
| 串口（UART） | 逐位传输的简单有线通信，常用于控制板 | 12 |
| MJPEG | 把每帧压成 JPEG 连续传输的视频流格式 | 12 |
| 光流（Optical Flow） | 通过像素移动估计物体运动 | 12 |
| 单应矩阵 | 描述两个平面之间投影关系的矩阵，用于图像拼接 | 12 |
| 逆运动学（IK） | 由末端目标位置反算各关节角度 | 12 |
