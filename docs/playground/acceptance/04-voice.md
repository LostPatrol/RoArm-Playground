# 中文语音控制

当前状态：**板端真实中文样本与网页自动启停通过；真人口令待实测**。最终结论统一以[状态表](../status.md)为准，不把样本或文字注入当成现场喊话验收。

## 目的

验证麦克风→真实离线 ASR→中文文本→动作规则的完整链路。

## 所需物品与前置

板端UQ212麦克风、ALSA、Vosk中文模型已部署。网页启动语音模式会自动启动板端speech worker，无需重复手工启动；停止、切换或转手动关节控制时结束worker和arecord。首次迁移的依赖/声卡配置见[host.md](../host.md)。仅输入文字不能替代说话测试。

## 网页操作

1. 打开“中文语音”并点击启动，等待自动worker显示音频在线。文字入口“执行文字口令”只调试文本到动作，单独记录，不计作真实语音验收。
2. 依次说“灯亮”“灯灭”“向左”“向右”“张开夹爪”“关闭夹爪”，等待每步完成。
3. 说“打招呼”“找人”，观察进入相应动作或模式。
4. 使用未定义口令，检查显示识别文本但不擅自执行动作；回到语音项目再测“停止”。
5. 点击停止或切换其他模式，检查原speech worker显示stopped、原arecord退出；要再次喊话时重新启动语音项目。

## 通过标准

真实说话能产生可见文本，已定义口令触发对应行为；未知文本提示未匹配。关节只需产生清楚可见的预期方向运动，不能用高精度作为门槛。离开语音模式后旧worker退出，不发送语音动作。

## 自动测试

在项目根目录使用项目 `.venv/bin/python`。

运行 `.venv/bin/python -m unittest discover -s tests -p test_host_worker.py -v` 检查音频转换和模式隔离；用 16kHz/16bit WAV、`--mode speech --wav <录音> --dry-run` 检查真实 ASR。合成文本接口测试不等于声学通过。

## 现场未验收

板端真实5.592秒中文样本识别“开放时间早上九点至下午五点”，完整推理含模型加载3.240秒；UQ212双声道16kHz采音成功。网页托管worker首次因DynamicUser缺HOME失败，显式设置HOME后voice启动9秒收到running心跳、停止为stopped，自动启停链路已实测。

现场短口令、噪声下识别和真人说话→机械动作仍待验收；文本注入运动已有实体测试但不计入声学准确率。“找人”会切换人脸模式并关闭旧语音麦克风进程。

## 失败定位

无文本：看worker状态与日志、arecord、设备和中文模型；`getpwuid`错误时检查子进程HOME是否为 `/var/lib/roarm-playground`。乱码/误识别：检查PCM格式和麦克风，先单人测试。文本正确但未执行：检查mode=voice及匹配短语。不要因无响应再启动第二个麦克风worker。
