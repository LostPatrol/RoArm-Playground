# 三维机械臂与夹爪实时拖动

现场状态：**待实测**。最终结论统一以 [状态表](../status.md) 为准；本文列验收方法，不预先宣布通过。

## 目的

把串口实测角度展示为可旋转三维几何示意；拖动模型夹爪时，把三维目标交给机械臂原厂逆运动学控制，比较请求目标与真实反馈。

## 所需物品与前置

串口四关节与 XYZ 反馈、支持 Canvas 的浏览器；实体机械臂和网页可同时观察。模型按厂家夹爪模式连杆尺寸绘制，加入 126.06 mm 底座高度；固件 XYZ 原点在肩关节，网页发送前扣除这段高度。模型为几何示意，不是已经完成标定的机械 CAD。

## 网页操作

1. 打开“三维机械臂”，默认启用“拖夹爪同步实体”；在画布空白处拖动只旋转视角。橙色夹爪外虚线圆表示可拖动区域。
2. 选择“垂直平面”，从橙色夹爪开始小幅拖动。末端保持在开始拖动时的径向垂直平面，控制臂伸展和高度；在“水平平面”中则保持开始拖动时的末端高度，改变 X/Y。
3. 拖动时实时发送带 `direct:true` 的 `cartesian` 请求，无需另点确认。网页用透视射线和平面交点计算目标毫米坐标；后端验证厂家 IK 可达性后发送 `T1041`，保持开始拖动时的实测夹爪角度。直接坐标控制首次用实测T102准备0/0运动参数，随后不逐段阻塞插补。
4. 对照“实测 XYZ”和“目标 XYZ”、上方四轴实测角度、实体和模型。实线模型始终由串口实测角度驱动，动画帧只在实测样本间插值；橙色圆环立即单独显示拖动目标，不能把圆环或请求已提交当作已经到位。
5. 使用右侧“水平拖动 / 垂直拖动”按钮也能启用两种平面；取消“拖夹爪同步实体”后，画布拖动只改变视角。若视线接近平面切向，网页提示先旋转视角再拖。
6. 用关节 ±5°、数字输入和实时滑条分别控制四轴，核对实体与模型的方向。停止按钮和离开网页会清除尚未发送的实时拖动请求，避免停车后继续排队发送旧目标。
7. 用未连接的本地服务或只读测试端观察离线状态，不把未更新模型当实时反馈。

## 通过标准

四关节模型变化来自实际反馈字段；地面、机械臂透视和前后遮挡方向合理。两种平面的小幅拖动能使实体向目标方向同步运动，真实 XYZ/角度随后变化；超出连杆或关节范围的目标应返回失败，不宣称执行成功。离线/过期数据明确显示。机械臂精度有限，本项按方向与实时交互验收，不要求毫米级到位。

## 自动测试

在项目根目录使用项目 `.venv/bin/python`。

运行 `.venv/bin/python -m unittest discover -s tests -p test_arm_controls.py -v` 检查原厂 INIT、力矩、绝对与相对 XYZ 协议、不可达目标拒绝；运行 `node tests/test_playground_ui.js` 检查原厂正运动学、多个视角的透视投影/平面回算、实时请求合并和停车顺序。完整自动测试使用 `.venv/bin/python -m unittest discover -s tests -v`。

浏览器核对 `/api/state` 的 `arm.joints`、`arm.raw.x/y/z`、`arm.cartesian_target` 与画布/文字输入。自动测试使用记录传输与假 DOM，不会连接实体，也不能证明实机 IK、夹爪配置或无线时延通过。

## 现场未验收

三维视角、手机布局、实体关节方向及两平面的真实拖动同步以主任务现场证据为准。连续拖动应观察实体停顿、目标请求延迟、反馈时间更新与实线模型动画，不能只凭一次成功请求判断顺滑。固件 `T1041` 只表示提交目标，不提供到位确认；后端以厂家夹爪模式逆解检查范围，实体机械结构、反馈偏差或固件配置差异仍需实际观察。最终证据以状态表/本轮报告为准。

## 失败定位

模型不动：先检查 `/api/state` 是否有实测 joints，再看脚本/绘图错误。不能开始拖动：确认已勾选同步并从橙色夹爪区域按下。目标超范围：缩小拖动距离；平面接近平行：先旋转观察视角。反向：核对关节符号和坐标轴。目标变而实测不变：检查 `T1041`、力矩是否开启、夹爪模式和串口错误。显示延迟：检查反馈时间与网页请求耗时，不能直接改用 targets 冒充实时实测。
