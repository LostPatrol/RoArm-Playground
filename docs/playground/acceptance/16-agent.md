# 现场 Agent 改规则挑战

现场状态：**待实测**。最终结论统一以 [状态表](../status.md) 为准；本文列验收方法，不预先宣布通过。

## 目的

现场给 Agent 一个具体小需求，展示代码修改、验证和真实效果变化的完整过程。

## 所需物品与前置

开发机项目和 Agent 可用，准备清晰修改入口：颜色阈值、语音规则或灯光动作等。选择能快速撤回的单点变更；根据最终部署流程同步设备。

## 网页操作

1. 打开“Agent改规则”，先演示当前规则并记录。
2. 提出具体变化，如“让指定口令点亮较暗灯光”或“改变默认追踪颜色”。
3. 查看实际代码 diff，执行相关测试，按部署说明同步并刷新。
4. 用相同输入再演示，观察规则真实变化。
5. 保存改前/改后代码与效果，最后恢复本场约定基线。

## 通过标准

有实际可审查代码 diff、相关测试和现场行为变化；页面入口或预先设好的参数切换不能冒充 Agent 写代码。实体能看出行为变化即可，普通运动不验收高精度。

## 自动测试

在项目根目录使用项目 `.venv/bin/python`。

修改颜色时运行 test_vision.py；修改语音 worker/计划规则时运行 test_host_worker.py；涉及控制时运行完整测试。通过现有测试仍需用实际输入检查新规则。

## 现场未验收

Agent现场可用性、修改所需时间、同步设备流程和真实规则变化待实测。

## 失败定位

只有聊天没有 diff：需求尚未落实。代码已变效果未变：检查实际部署文件、服务进程和浏览器缓存。测试失败应修复或撤回，不删改失败测试以宣称完成。

记录日期、软件版本、输入物品/人员、实际效果与失败现象；保存关键状态、截图或录像，不把自动测试结果替代实体证据。
