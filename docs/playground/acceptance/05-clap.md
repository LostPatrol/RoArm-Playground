# 拍手导演与节奏律动

当前状态：**USB采音、启动预热与网页自动启停通过；真人拍手待实测**。最终结论统一以[状态表](../status.md)为准，事件注入不等于麦克风检测到拍手。

## 目的

验证实际 PCM 声能突变触发节拍，观察机械臂和灯光按次数交替回应。

## 所需物品与前置

板端UQ212麦克风和ALSA已配置，网页自动启动clap worker，无需重复手工启动；停止/切换时结束旧worker与arecord。部署配置见[host.md](../host.md)。该算法是声能突变检测，不是训练过的拍手音类别识别器。先在安静环境检查噪声。

## 网页操作

1. 打开“拍手律动”并点击启动，等待自动音频worker在线，保持安静数秒；live输入先预热0.5秒。“发送一次明确的拍手测试事件”仅注入事件，不证明麦克风检测到拍手。
2. 单次拍手，观察节拍计数、灯光和底座小幅动作。
3. 间隔约一秒连续拍五次，对照现场声音和事件次数。
4. 播放持续较响声音，并观察节拍动作期间的机械噪声是否误触发；停止/切换后确认旧clap worker为stopped，再拍手不触发旧律动。

## 通过标准

明确的单次拍手可触发单次事件，持续声音不按每个音频块重复触发；节拍带来交替灯光/小幅底座动作。记录误报，不宣称能区分所有环境声音。模式退出后不触发新动作。

## 自动测试

在项目根目录使用项目 `.venv/bin/python`。

运行 `.venv/bin/python -m unittest discover -s tests -p test_host_worker.py -v`，验证静音→峰值、冷却与持续响声；用 `--mode clap --wav <16kHz录音> --dry-run` 做真实录音复测。

## 现场未验收

已用UQ212真实录音定位启动瞬态：原始样本曾误报1次，证据保留；加入0.5秒live预热后6秒只读采音无启动误报。网页clap worker运行9秒收到running心跳、停止为stopped；注入节拍驱动实体底座/灯光已有测试。

真人拍手响应、机械噪声、连续律动及误触发率仍待实测，不把静音测试或生成PCM波形当作现场拍手。

## 失败定位

无响应：查看音频worker状态、RMS、设备采样和默认0.10阈值；误报：按host只读诊断流程调整阈值并复测，避免麦克风正对舵机。多次漏报：拍手间隔须超过冷却窗口，检查削波。停止网页模式后再手工诊断，避免两路worker争用麦克风。
